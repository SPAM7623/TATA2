PROJECT OVERVIEW
═══════════════════════════════════════════════════════════════════════════════

OBJECTIVE:
  Predict surface defects on steel coils from 49 process-sensor measurements

PROBLEM CHARACTERISTICS:
  • Dataset Size: 1352 training samples, 339 test samples
  • Features: 49 anonymised process variables (X1-X49)
  • Target: Binary classification (defect=1, non-defect=0)
  • Class Imbalance: 19.5:1 (66 defects, 1286 normal)
  • Missing Values: 249 cells (0.38%) in training data
  • Challenge: Extreme imbalance + small sample size = high overfitting risk

KEY METRICS (Final 5-Seed Ensemble):
  • ROC-AUC: 0.8668 (primary ranking metric)
  • PR-AUC: 0.3136 (precision-recall for imbalanced data)
  • F1-Score: 0.403 (at threshold 0.5025)
  • Recall: 0.455 (catch 45.5% of defects)
  • Precision: 0.361 (36.1% correct when predicting defect)

DESIGN DECISIONS FROM EDA:

  ✓ Apply strong regularisation (L1/L2, subsample, colsample)

PHASE 3: BASELINE MODEL (SINGLE-SEED)
──────────────────────────────────────
File: clean_pipeline/03_baseline_model.py

Model Configuration (Regularised XGBoost):
  • Algorithm: XGBClassifier
  • Seed: 42 (reference seed)
  • max_depth: 3 (shallow, prevents overfitting)
  • n_estimators: 300 (sufficient trees)
  • learning_rate: 0.03 (slow, stable learning)
  • reg_alpha: 0.5 (L1 regularisation)
  • reg_lambda: 2.0 (L2 regularisation)
  • min_child_weight: 3 (leaf size control)
  • subsample: 0.7 (70% row sampling)
  • colsample_bytree: 0.7 (70% column sampling)
  • scale_pos_weight: 19.5 (imbalance compensation)

Evaluation Method:
  • 5-fold stratified cross-validation
  • Out-of-fold (OOF) predictions
  • No data leakage
  • Honest metrics on unseen folds

Results (5-fold OOF):
  • ROC-AUC: 0.8647 (baseline reference)
  • PR-AUC: 0.3055
  • F1: 0.395 @ threshold 0.5025
  • Recall: 0.455 (45.5% defects caught)
  • Precision: 0.349 (34.9% correct when predicting defect)
  • MCC: 0.363 (balanced metric)
  • Balanced Accuracy: 0.705
  • Confusion Matrix: TP=30, FP=56, FN=36, TN=1230

Interpretation:
  - Model learned meaningful pattern (0.8647 is strong)
  - Better than random (0.5) but room for improvement
  - Reference point for ensemble comparison

PHASE 6: IMBALANCE STRATEGY COMPARISON
───────────────────────────────────────
Files:
  • PART_6_IMBALANCE_STRATEGY_COMPARISON.py
  • part6_imbalance_handling.py

Strategies Tested:
  1. SMOTE (Synthetic Minority Oversampling Technique)
     • Generates synthetic defect samples
     • Balances training set to 1:1
     • Issue: Train metrics inflate, OOF metrics drop
     • Verdict: ❌ REJECTED (causes overfitting)

  2. scale_pos_weight=19.5 (our choice)
     • Weights loss function: penalizes defect misclassification 19.5x
     • No synthetic data generation
     • Prevents overfitting on small dataset
     • Verdict: ✅ CHOSEN (proven best)

Evidence:
  • SMOTE: Train ROC-AUC high, OOF ROC-AUC low (overfitting signal)
  • scale_pos_weight: Train and OOF ROC-AUC consistent (no overfitting)
  • scale_pos_weight integrated into all models (standard in XGBoost)

Decision:
  ✅ scale_pos_weight=19.5 prevents overfitting
  ❌ SMOTE generates unrealistic synthetic samples

PHASE 11: TRAINING 5-SEED ENSEMBLE & CACHING
──────────────────────────────────────────────
File: clean_pipeline/05_train_5seed_ensemble.py

Two Steps:

  Step A: Cross-Validation (OOF Predictions)
    • 5-fold stratified CV
    • Train 5 models (seeds [42, 123, 999, 2025, 7777])
    • Generate out-of-fold predictions
    • Output: oof_predictions.csv (cached)

  Step B: Refit on All Data
    • Train 5 models on COMPLETE training set
    • One model per seed
    • Generate test predictions
    • Average 5 predictions: (p1 + p2 + p3 + p4 + p5) / 5
    • Output: test_probabilities.csv (cached)

Caching Strategy:
  ✅ OOF predictions cached (1352 × 2 cols)
  ✅ Test probabilities cached (339 × 2 cols)
  ✅ Instant threshold application (no retraining)
  ✅ Efficient: Train once, predict many times

Results:
  • 5-seed ensemble OOF ROC-AUC: 0.8668
  • 5-seed ensemble OOF PR-AUC: 0.3136
  • F1: 0.403 @ threshold 0.5025
  • Trained 5 models in parallel/sequence
  • Probabilities averaged (not voting classification)

═══════════════════════════════════════════════════════════════════════════════
KEY HYPERPARAMETERS & WHY THEY MATTER
═══════════════════════════════════════════════════════════════════════════════

max_depth=3 (Shallow Trees)
  • Default: 6, We use: 3
  • WHY: Only 66 positive examples
  • EFFECT: Prevents overfitting, generalizes better
  • TRADE-OFF: Slightly lower training accuracy, better validation

n_estimators=300 (Number of Boosting Rounds)
  • Default: 100, We use: 300
  • WHY: More iterations = more refinement
  • EFFECT: Stabilizes model, captures complexity
  • TRADE-OFF: Longer training time (negligible)

learning_rate=0.03 (Shrinkage)
  • Default: 0.3, We use: 0.03
  • WHY: Small steps = slower, more stable learning
  • EFFECT: Better generalization, lower overfitting
  • TRADE-OFF: More iterations needed for convergence

reg_alpha=0.5 (L1 Regularisation)
  • Default: 0, We use: 0.5
  • WHY: Encourages feature sparsity
  • EFFECT: Simpler models, fewer active features
  • TRADE-OFF: May discard some useful features

reg_lambda=2.0 (L2 Regularisation)
  • Default: 1.0, We use: 2.0
  • WHY: Stronger penalty on leaf weights
  • EFFECT: Prevents large weight values, smooths model
  • TRADE-OFF: May reduce predictive power if too strong

min_child_weight=3 (Minimum Child Weight)
  • Default: 1, We use: 3
  • WHY: Prevents splits on small, noisy groups
  • EFFECT: Less complex trees, more stable predictions
  • TRADE-OFF: May miss subtle patterns

subsample=0.7 (Row Sampling)
  • Default: 1.0, We use: 0.7
  • WHY: Don't use all rows for each tree
  • EFFECT: Regularisation, prevents overfitting
  • TRADE-OFF: Increased variance, mitigated by ensemble

colsample_bytree=0.7 (Column Sampling)
  • Default: 1.0, We use: 0.7
  • WHY: Don't use all features for each tree
  • EFFECT: Encourages diverse trees, better ensemble
  • TRADE-OFF: Each tree weaker, ensemble stronger

scale_pos_weight=19.5 (Imbalance Compensation)
  • Default: 1.0, We use: 19.5
  • WHY: 19.5:1 class imbalance
  • EFFECT: Penalizes defect misclassification 19.5x
  • TRADE-OFF: Changes probability scale, requires calibration

ENSEMBLE: 5 Seeds [42, 123, 999, 2025, 7777]
  • WHY: Different random initializations
  • EFFECT: Average out model variance
  • TRADE-OFF: 5x training time, +0.0021 AUC gain
  • VERDICT: Worth it for stability

WHAT WORKED & WHAT DIDN'T
═══════════════════════════════════════════════════════════════════════════════

✅ WORKED (Adopted)
──────────────────
1. Regularised XGBoost
   - Shallow trees + strong regularisation
   - ROC-AUC: 0.8647

2. scale_pos_weight=19.5
   - Imbalance handling without synthetic data
   - Proven stable, no overfitting

3. Median Imputation (Leakage-Free)
   - Zero missing values
   - Prevents data leakage

4. Multi-Seed Ensemble (5 seeds)
   - +0.0021 AUC improvement
   - Variance reduction
   - More stable predictions

5. Shallow Trees (depth=3)
   - Prevents overfitting on 66 examples
   - Better generalisation


❌ DIDN'T WORK (Rejected)
───────────────────────
1. Feature Engineering
   - Added 30+ new features
   - Result: ROC-AUC ↓ 0.0174 (worse)
   - Reason: Overfitting on small dataset

2. Probability Calibration
   - Isotonic regression & Platt scaling
   - Result: ROC-AUC ↓ 0.0200 (worse)
   - Trade-off: Better Brier, worse AUC

3. SMOTE Oversampling
   - Generated synthetic defect samples
   - Result: Train ↑, OOF ↓ (overfitting)
   - Reason: Unrealistic synthetic data

4. LightGBM & CatBoost
   - Alternative gradient boosting
   - Result: ROC-AUC 0.8545 < 0.8647 (XGB better)
   - Reason: Different regularisation strategy

5. Heavy Ensemble (3+ models)
   - XGB + LightGBM + CatBoost blends
   - Result: No improvement over single XGB
   - Reason: Added complexity without benefit
